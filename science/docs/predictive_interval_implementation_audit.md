# Predictive interval implementation map and branch decision

Scope: the current paper-facing controller and its evaluated finite-horizon monitor. The instantaneous certificate, physical model, frozen numerical evidence, and Proposition 2 were not changed in this patch. Baseline before edits: commit `682493bf13f0b2a1099eeacf6f1b6b7395bf6565`, existing regression **33/33 PASS**.

## Executed path

1. `src/controllers/paper_safety_controller.py::PaperIntegratedSafetyController` inherits `IntegratedSafetyController._predict` and overrides `_uncertainty` and `_build_context`. `_uncertainty` supplies grade, predecessor acceleration/jerk, mass/drag/rolling force, actuator-lag, heat/cooling, ambient, message-delay, and auxiliary-availability intervals. `_build_context` evaluates the instantaneous hard rows at the current point state; at `speed <= low_speed_threshold` it selects the zero-order-hold thermal row.
2. `src/controllers/integrated_safety_controller.py::run_cycle` measures and constructs hard rows, solves the normal hard QP for the provisional command, invokes `_predict`, aggregates the returned value with age-aware upstream messages, selects a supervisor mode, and reverifies a changed final command. `_predict` constructs a speed-affine, saturated backup extension and the reserve callback.
3. `src/safety/predictive_reserve.py::compute_predictive_reserve` starts from a point interval state. For prediction step 1 it passes `provisional_executed_control` to `propagate_interval_one_step`. At every later step it passes `backup_policy_extension(current, step)`. It records interval states and reserve values, then returns the minimum over steps as `rho_cert_H`. This sequencing matches the first/later-command order in the manuscript, but not by itself a sound-enclosure proof.
4. `src/safety/reachable_set.py::saturated_affine_backup_extension` forms two affine functions of the speed interval and calls `interval_clip` with bounds from the **current** controller context. `propagate_interval_one_step` applies an explicit-Euler interval plant to position, speed, friction/auxiliary force, temperature, predecessor motion, and gap. It passes `gear_id` through unchanged, advances dwell time, and adds a communication-delay interval to message age.
5. `src/controllers/integrated_safety_controller.py::_predict.lower` starts from the **current** `CompleteCertificate` and subtracts empirical tube-width offsets to construct purported intervals for friction gap, auxiliary gap, collision reserve, and, when already active, the low-speed thermal gate. `src/safety/conflict_reserve.py::compute_interval_certificate_lower_bound` normalizes their lower endpoints and selects the minimum. It does not re-evaluate every hard certificate component over the predicted state box.

## Interval arithmetic and exceptional states

`src/safety_core.py::Interval` stores Python `float` endpoints. Addition, negation/subtraction, four-corner multiplication, reciprocal/division, and square use native round-to-nearest arithmetic; no IEEE directed mode, `nextafter`, interval library, or per-operation outward inflation is used. `interval_clip` and `_nonnegative` use endpointwise scalar `min`/`max` but inherit the same floating-point limitation. No general interval exponential, intersection, union, or branch-hull operation is implemented on this path. Ordinary natural interval dependency inflation is present and is not itself an error.

The interval constructor rejects `low > high` but does not reject NaN/Inf. Overflow and underflow are not handled as enclosure failures. `reciprocal` raises `ZeroDivisionError` if the denominator contains zero, including `[0,0]`; a nonzero point denominator is processed without outward rounding. Selected positive uncertainty scales and nonnegative delay are checked, not every finite physical/map domain. The predictive API has no explicit invalid/unavailable certificate state guaranteed to force a fail-closed supervisory transition for all these cases.

## Branch and reserve gaps

- `src/simulator/gearbox.py::{can_shift,shift_gear,advance_dwell_timer}` defines admissible gear/dwell behavior for point states, but the predictive interval map does not enumerate all admissible shifts or hull their continuous outcomes. Holding the current `gear_id` would require a separate proof that no shift can occur throughout each interval step; none is present.
- `PaperIntegratedSafetyController._build_context` selects the low-speed branch at the current speed. The predicted speed interval can straddle the threshold without evaluation and hull of both zero-order-hold and high-speed thermal certificate branches. Fade and auxiliary limiting maps are likewise not rebuilt as sound interval functions over each box.
- The affine-saturation backup extension only encloses its reference formula in exact arithmetic under fixed supplied bounds; it does not prove coverage of state- and gear-dependent physical limits or all backup-feedback branches.
- `_predict.lower` uses `0.02 * gap_width`, `1e-5 * brake-force widths`, and temperature width around the current certificate. There is no global derivative/sensitivity proof or natural interval evaluation showing those offsets enclose future `Delta_f`, `Delta_a`, `M_i`, and `g_i^{T0}` for every state in a predicted box. Taking a minimum of these values therefore cannot establish `rho_i^{IA}(X) <= inf_{chi in X} rho_i(chi)`.

These are independent gaps. Adding `nextafter` to the scalar arithmetic alone would **not** establish a sound predictive certificate: gear/dwell, low-speed, backup, reserve, and invalid-state semantics still require a substantial implementation redesign and new deterministic tests. This exceeds the requested micro-patch. **Branch B** is therefore selected; no scientific/control/QP algorithm was altered and no new interval layer or new IA test suite was introduced.

## Interpretation and acceptance boundary

The instantaneous `rho_i` remains the declared two-command hard-set nonemptiness test. Proposition 2 remains mathematically conditional on its sound state and reserve enclosure assumptions. The evaluated `rho_cert_H` is a numerical predictive-monitor value, **not** a formally assured outward lower bound. Negative values are inconclusive warnings, not proofs of future infeasibility. The existing 5,000 sampled-state tube checks (and 32,849 stored contemporaneous sign checks) are regression/empirical consistency evidence only, not formal containment of all model trajectories. Sound numerical implementation would require every elementary operation, discrete branch, backup command, certificate component, and exceptional state to be covered, followed by formal argument and tests; real-truck uncertainty coverage and field safety would remain separate questions.
