# Phase 2C-3 formal matched learning protocol

This document registers the formal learning comparison before any final run is inspected. The machine-readable authority is `configs/learning/formal_learning_protocol_v1.yaml`; it is JSON-formatted YAML so it can be parsed by the Python standard library without introducing an unverified parser dependency. Its byte-level SHA-256 is the protocol identity.

## Matched design

The primary comparison is `SAFE-MAPPO-DIFFQP` versus `SAFE-MAPPO-STOPGRAD`, using ten paired training seeds. Each pair has identical actor and critic initialization, PyTorch random stream, scenario order, rollout and PPO budget, reward, optimizer settings, and accepted two-dimensional forward QP. PPO likelihood is evaluated only at the nominal action (u_{RL}); the environment transition is generated by (u_{final}). The sole intended method difference is whether the provisional QP output contributes its valid implicit derivative to the already-declared intervention objective. StopGradient evaluates the same loss value with that output path detached.

The actor and critic each use the existing one-hidden-layer tanh architecture with 32 hidden units. Training uses 20 updates, 12 environment steps per update, three controlled trucks, two PPO epochs, and 18-sample minibatches. There is no early stopping. The final checkpoint is update 20; no test-set checkpoint selection is permitted.

## Reward and differentiable intervention term

The reward is a frozen normalized sum of speed tracking, spacing tracking, control effort, friction use, auxiliary use, provisional-QP intervention, and negative predictive-certificate terms. Numerical scales and weights are in the protocol. Those weights are experimental design coefficients, not physical parameters. The same scalar reward and the same intervention-objective coefficient are used by both methods.

For training-state hard rows (Gz\le h), the intervention term uses the provisional projection (u_{\star0}). DiffQP differentiates the term through (u_{\star0}(u_{RL})) only when the Phase 2C-2 regularity gates pass; invalid cases use the registered zero-gradient fallback. StopGradient detaches only that output path. The direct dependence on (u_{RL}) is retained in both branches. Supervisor, predictive certificate, hard-row construction, and physical dynamics remain detached.

## Scenarios and evaluation

Training follows a fixed seven-case cycle: nominal descent, hot-brake descent, grade transition, leader braking, communication delay/loss, low-speed operation, and a heterogeneous three-truck platoon. The same seven cases form the held-out deterministic evaluation suite. Communication realizations are deterministic conditional on each registered evaluation seed. Checkpoints 0, 10, and 20 are evaluated with evaluation seeds 38101--38103 for ten steps per case.

Previously documented M8, M7, and M9 limitations remain unchanged. This phase does not reinterpret or replace Phase 2M evidence.

## Metrics and statistics

Raw per-update and per-evaluation data retain return, nominal hard-feasibility, both intervention norms, instantaneous and predictive reserves, certificate losses, supervisor occupancy, tracking error, peak temperature, braking energies, mission completion, timings, and all DiffQP regularity/fallback diagnostics. Raw curves are not smoothed.

Final paired inference uses the ten training-seed differences. Each outcome reports mean, sample standard deviation, median, a 10,000-replicate paired bootstrap 95% interval, Cohen's (d_z), and an exact two-sided sign-flip permutation p-value. Holm correction covers five pre-registered outcomes: final return, return AUC, intervention frequency, intervention norm, and nominal hard-feasible rate. Sample efficiency is the trapezoidal area under the held-out checkpoint-return curve divided by final environment steps; no post-hoc threshold is used.

`SUPPORTED` requires a favorable paired mean, a favorable bootstrap interval excluding zero, and Holm-adjusted (p\le0.05). `PARTIALLY_SUPPORTED` requires a favorable interval excluding zero without the Holm gate. A statistically adverse result is `NOT_SUPPORTED`; an interval spanning zero is `INCONCLUSIVE`. A confidence interval spanning zero is never treated as proof of equality. Because both methods share the same forward controller, a differential safety claim is not made without positive executed-outcome evidence.

## Freeze and integrity gates

Before formal execution, the implementation, protocol, and integrity test are committed. Each run records the Git commit, protocol/config/model/controller hashes, registered seed, paired initial and final checksums, checkpoint hashes, raw-log hash, and formal provenance. Completed raw files and checkpoints are made read-only. The result manifest rejects missing or duplicate seeds, DEBUG provenance, pairwise initialization mismatches, controller-hash mismatches, and any hash failure.

No Abstract, Introduction, or Conclusion claim is edited in Phase 2C-3. Figures and tables are generated from immutable logs for later manuscript integration.
